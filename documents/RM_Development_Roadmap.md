# 프로젝트 개발 로드맵

본 문서는 **"Vision AI 기반 자율주행 모형 차량 원격 호출 및 정밀 주차 시뮬레이션 시스템"**의 성공적인 구현을 위해 20년차 자율주행 시스템 엔지니어링 관점에서 설계한 단계별 상세 개발 계획입니다.

---

## 단계별 상세 개발 계획

### 1단계: 개발 환경 구축 및 로봇(Linorobot2) 센서 데이터 검증
* **목표:** 가상 로봇의 센서 데이터 발행 여부 및 구동성 확인
* **세부 태스크:**
  - Ubuntu 22.04 LTS 및 ROS2 Humble 내 `linorobot2` 관련 패키지 의존성 설치
  - Gazebo 시뮬레이터에서 로봇 모델 생성
  - `/scan`(3D-LiDAR), `/camera/image_raw`(카메라) 토픽의 수신 주기(Hz) 정상 여부 모니터링
  - `teleop_twist_keyboard`를 이용한 수동 동작 및 오도메트리(`/odom`) 데이터 정밀도 테스트
* **검증 방법:** RViz2를 띄워 LiDAR 센서 포인트와 카메라 화면이 깨지지 않고 딜레이 없이 시각화되는지 확인

### 2단계: 아커만 조향(Ackermann Steering) 4륜 로봇 모델 구축 및 조향/구동 검증 [신규 반영]
* **목표:** 기존 차동 구동(Diff Drive) 방식 대신 실제 승용차 형태의 4륜 아커만 조향 로봇 모델(`ackermann.urdf.xacro`) 구축
* **세부 태스크:**
  - `ackermann_drive.urdf.xacro` 컨트롤러 파일 신규 작성 (전륜 조향 + 후륜 구동 플러그인 연동)
  - `ackermann.urdf.xacro` 4륜 차체 및 3D-LiDAR/카메라 센서 통합 모델 파일 신규 작성
  - `export LINOROBOT2_BASE=ackermann` 지정 후 Gazebo 시뮬레이터 구동 테스트
  - 수동 조종을 통한 전륜 조향 각도(Steering Angle) 꺾임 및 오도메트리(`/odom`) 데이터 정확도 검증
* **검증 방법:** Gazebo 화면에서 차량 이동 시 앞바퀴 2개가 곡선 궤적에 맞춰 좌우로 물리적으로 꺾이고, 최소 회전 반경 제약 하에 정상 주행하는지 확인

### 3단계: SLAM을 통한 정적 2D 격자 지도(Map) 작성
* **목표:** 아커만 4륜 로봇 주행의 뼈대가 될 가상 주차장/주행로 환경의 2D 지도 생성
* **세부 태스크:**
  - `slam_toolbox` 또는 `cartographer` 패키지 구동
  - 4륜 아커만 로봇을 수동 조종하며 주변 공간 매핑
  - `map_saver_cli`를 사용해 지도 데이터(`map.yaml`, `map.pgm`) 저장
* **검증 방법:** 저장된 격자 지도가 실제 Gazebo 맵 형태를 왜곡/노이즈 없이 반영하고 있는지 확인

### 4단계: ROS2 Nav2 기반 아커만 자율주행 프레임워크 구축
* **목표:** 아커만 동역학(회전 반경 제약)을 반영하여 임의 목적지까지 장애물을 피해 도달하는 주행 성능 확보
* **세부 태스크:**
  - Nav2 AMCL(위치 추정) 및 Costmap(장애물 지도) 설정
  - 아커만 제어를 지원하는 로컬 경로 계획기(`RegulatedPurePursuitController` 또는 `TEB Local Planner`) 적용
* **검증 방법:** RViz2 상에서 목적지 지정 시, 제자리 회전 없이 실제 자동차처럼 큰 호를 그리며 충돌 없이 목적지에 도달하는지 확인

### 5단계: Qt 대시보드 UI 및 시스템 매니저 통신 연동
* **목표:** 사용자 조작 리모컨 인터페이스와 로봇 시스템 제어기 간의 통신 프로토콜 안착
* **세부 태스크:**
  - `qt_dashboard_node`(C++/Qt) 구현: 호출 버튼 및 LED/경보 사운드 위젯
  - `system_manager_node`(C++) 구현: 전체 모드를 관리하는 유한 상태 머신(FSM) 설계
  - 호출 신호(`/remote_call`)에 따른 모드 전이 및 목적지(`/goal_pose`) 송신 연동
* **검증 방법:** Qt GUI에서 버튼 클릭 시 차량 정보 및 주행 상태(LED 녹색)가 연동되어 올바르게 깜빡이는지 확인

### 6단계: Vision AI (YOLO 등) 객체 인지 모듈 개발
* **목표:** 전방 카메라 영상을 활용해 주차 공간 타겟(벽, 기둥) 및 돌발 장애물 실시간 검출
* **세부 태스크:**
  - ROS2 이미지 토픽을 수신하여 YOLO 추론 모델을 구동하는 Python 노드 작성
  - 검출된 객체의 상대 위치를 좌표계 변환을 거쳐 `/detected_objects`로 발행
* **검증 방법:** 기둥이나 벽이 카메라에 잡혔을 때, 정확한 객체 태그와 상대 좌표 거리가 퍼블리시되는지 로그 확인

### 7단계: 센서 융합 기반 장애물 회피 및 고립 판단 (Fail-Safe)
* **목표:** 주행 경로 장애물로 인해 전방이 막혔을 때 고립 상황을 감지하여 비상 정지 수행
* **세부 태스크:**
  - 3D-LiDAR 포인트와 Vision AI 데이터를 융합 분석하는 `obstacle_avoidance_helper_node` 구현
  - 회피 불가 상황 발생 시 즉각 비상 대기 상태 전환 신호(`/path_blocked`) 발행
* **검증 방법:** 로봇이 사방이 막힌 곳에 도달했을 때 안전하게 즉시 정지하고 대시보드 상에 적색 경보(알람)가 울리는지 확인

### 8단계: 강화학습(RL) 기반 초정밀 밀착 주차 노드 구현
* **목표:** 호출기 반경 1m 영역 진입 시, 타겟 기둥/벽면에 오차범위 10cm 이내로 밀착 주차 기능 구현
* **세부 태스크:**
  - Gazebo 환경과 연동 가능한 강화학습 전용 가상 훈련 환경(Gym env) 설계
  - 아커만 제어 특성을 고려한 최적 밀착 정차 보상 함수(Reward Function) 설계 및 에이전트 훈련
  - Nav2(일반 주행)에서 RL 주차 에이전트로 제어권(`cmd_vel`)을 매끄럽게 인계하는 핸드오버 로직 구축
* **검증 방법:** 시뮬레이션 주차 성공률(기둥 및 벽면 충돌 없이 10cm 이내 안착) 분석

### 9단계: 시스템 통합 및 예외 처리 종합 검증
* **목표:** PRD에 명시된 모든 시나리오(TC 1 ~ TC 3) 완벽 재현 및 테스트 검증
* **세부 태스크:**
  - 센서 통신 강제 단절 상황에서의 Fail-Safe 정지 및 알림 작동 여부 검증
  - 다양한 동적 장애물 배치 상황 속 주행 기능 검증
  - 전 시나리오의 자동화 테스트 결과 분석 및 시스템 안전 종료 루틴 검증
* **검증 방법:** 모든 단위 테스트 케이스의 통과 여부 검증 및 예외 없는 작동 확인
