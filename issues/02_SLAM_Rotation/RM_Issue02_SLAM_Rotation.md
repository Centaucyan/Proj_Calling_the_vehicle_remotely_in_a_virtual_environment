# Issue 02: SLAM Mapping 중 지도(장애물)가 시계방향으로 회전하며 왜곡되는 현상

## 1. 문제 증상 (Symptoms)
- `slam_toolbox`를 이용해 지도를 생성할 때, 로봇이 직진을 하더라도 RViz2 상에서 라이다 포인터(검은색 장애물 픽셀)들이 로봇 쪽으로 훅 다가오거나 맵 전체가 시계방향으로 빙글빙글 도는 현상 발생.
- 실제 Gazebo에서는 로봇이 똑바로 전진하지만, 생성되는 맵은 지속적으로 회전하며 겹쳐서 찍히고 찌그러짐.

## 2. 원인 분석 (Root Causes)
이 문제는 단일 원인이 아니라, 여러 가지 설정 오류가 겹쳐서 발생한 복합적인 문제였습니다.

- **원인 A: 바닥 스캔 데이터를 장애물로 인식 (가장 결정적 원인)**
  - 3D 라이다 센서가 바닥을 향해 쏜 레이저(동심원 형태의 포인트 클라우드)를 `pointcloud_to_laserscan` 노드가 벽(장애물)으로 변환하여 SLAM에 전달함.
  - 로봇이 이동할 때 바닥의 레이저 원도 항상 같은 거리로 함께 이동하므로, SLAM 알고리즘은 "거대한 장애물(바닥)이 로봇과 같이 움직인다"고 착각함. 이로 인해 오도메트리 이동량을 강제로 축소시키거나 지도를 억지로 회전시키는 왜곡을 발생시킴.
- **원인 B: `joint_state_publisher` 중복 실행에 따른 TF 충돌**
  - `launch_sim.launch.py` 내에서 실제 가제보 관절 상태를 읽어오는 `joint_state_broadcaster`와 모든 관절을 강제로 0도로 만드는 더미 노드인 `joint_state_publisher`가 동시에 실행됨.
  - 두 노드가 하나의 토픽을 두고 데이터를 엎어치며 싸우게 되어, TF 트리가 깜빡거리고 오도메트리 정합성에 치명적인 에러 유발.
- **원인 C: 조향축(Steering) PID 부재 및 가짜 오도메트리 발생**
  - 가제보 물리엔진 상에서 앞바퀴 조향축을 0도(직진)로 꽉 잡아주는 PID 값이 없어서, 차체 하중에 의해 바퀴가 물리적으로 미세하게 틀어지며 곡선 주행함.
  - 실제 슬립(미끄러짐)으로 인한 좌우 바퀴 속도 오차를 제어기가 그대로 피드백받아 가짜 회전 오차로 누적시킴 (`open_loop: false` 설정의 한계).

## 3. 해결 방법 (Solutions)

- **조치 1: 바닥 스캔 데이터 필터링 (`slam_mapping.launch.py`)**
  - `pointcloud_to_laserscan` 파라미터 중 `min_height`를 `-0.3`에서 `-0.1`로 상향 조정.
  - 라이다 장착 높이(0.35m)를 고려하여 지면(0m) 부근에 닿는 레이저를 완전히 무시, 실제 서 있는 기둥과 벽면만 스캔되도록 필터링.
- **조치 2: 충돌하는 더미 노드 주석 처리 (`launch_sim.launch.py`)**
  - `joint_state_publisher` 노드 실행 부분 및 LaunchDescription 반환 부분을 주석 처리하여 조향각 TF 충돌 원천 차단.
- **조치 3: 앞바퀴 수동 관절(Passive Joint) 등록 (`ros2_control.xacro`)**
  - 더미 노드를 껐을 때 RViz2에서 앞바퀴 모델이 사라지는 현상을 막기 위해, 앞바퀴 2개를 `<state_interface>`만 갖춘 수동 관절로 등록. 가제보에서 굴러가는 실제 바퀴 회전 상태만 읽어오게 조치.
- **조치 4: 오도메트리 튜닝 및 조향 PID 주입 (`ackermann_controllers.yaml`)**
  - `open_loop: true`로 설정하여 물리적인 바퀴 슬립 노이즈를 무시하고 `cmd_vel` 명령 기반의 깨끗한 오도메트리(직진 명령 시 완벽한 0도 회전)를 사용하도록 강제.
  - `gazebo_ros2_control` 파라미터에 앞/뒷바퀴 4개 관절에 대한 `pid_gains(p: 100.0, i: 0.0, d: 1.0)`를 명시하여 물리엔진 상에서 조향이 틀어지지 않도록 단단히 고정.
